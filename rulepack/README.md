# rulepack/v1.json

The rule pack of blueprint section 9.10: the data file the safety-intent matcher reads before any model call and
again over every outbound artefact. Its shape is `contracts/rulepack.schema.json` (`RulePack`, version "1"). The
reference matcher is `harness/rulepack.py`; the application's TypeScript port reads the same file and pins the same
constants. Every corpus-derived value in the file is regenerated by `uv run python -m harness.rulepack --refresh`
(the protective rows from the eight C&E sheets, the outbound fixture from the classifier over the approved lessons)
and the file must not change under a refresh; nothing in it is typed from memory.

## How the matcher reads the file

- Tokens are lower case. A tag stays whole (`vshh-1201`, `seq-3401`) and also matches its alphabetic prefix, so
  `psv-8901` matches the generic token `psv`; every other run of letters or digits is one token, so `car-seal` and
  `car seal` match alike. A `*` inside a phrase matches 0 to 3 tokens (`GAP`).
- Protective tokens are every `generic_protective_tokens` entry and, for each `protective_vocabulary` row, its
  `equipment_tag`, `seq_id`, `initiators` and every tag inside its permissive lines and effect actions
  (`protective_terms`). `protective_function` is the row of the first such token in the text. On a
  `control_loop_only` row `initiators` lists the sheet's control, alarm and relief layer tags.
- Rules run in pack order. R1: a `permanent_change` verb phrase within `window_tokens` of a protective token or a
  `permanent_change` noun. R2: a surviving defeat phrase whose object is a protective token, one that starts inside the
  phrase or within 4 tokens after it (`OBJECT`). R3: a `documented_bypass_entities` entity is named and a
  `procedure_phrases` phrase occurs. R4: a surviving defeat phrase without such an object. R5: none. `window_tokens`
  counts the tokens between two phrases.
- A defeat phrase survives when it is within `window_tokens` of a protective token and none of the four suppressions
  removes it: `named_artefacts` (the phrase overlaps an artefact name: "manual bypass", "inhibit permit");
  `record_labels` (a label follows within 2 tokens: "the bypass register entry"); `passive_record_question_markers`
  (a marker precedes within 2 tokens while a record label occurs anywhere: "which trips were overridden ... is it
  recorded"); `negation_prefixes` (one precedes within 2 tokens: "never defeat", "says do not defeat"). With
  `standalone_without_permit`, a permit phrase (a defeat phrase that contains "permit" or "izin" and no defeat word:
  "without a permit", "no permit", "tanpa izin") reports a missing permit and counts only beside another surviving
  defeat phrase.
- `permanent_change.verbs_en` and `verbs_id` carry the change verb with its object where precision needs it
  ("replace * spring", "remove * trip from") and the bare markers that stand alone ("permanently", "de-rate",
  "uprate", "re-range"); `nouns` are the protective objects a permanent change names, each also a generic protective
  token. "re-range" is not a noun: OPL-GA-1201A-07 uses the word as a noun in a troubleshooting row, and a noun that
  fires on its own would block that approved lesson at the outbound gate.
- `documented_bypass_entities` binds each entity to the lesson that documents it, verified in the corpus through
  `harness.pdftext.opl_texts`: HV-6701 and the manual bypass in OPL-LV-6701-05, whose safety section also carries the
  authorised override permit sentence, so the permit entities bind there; the test/inhibit permit and ESD/override
  control sentence in OPL-LV-6701-06, whose section 2 places the function to bypass/inhibit under permit, and the
  proof-test entities with it (the golden set's own binding); car-seal and pop test in the two PSV lessons, so each of
  those entities has one row per lesson. `classify` reports the entity string; the application resolves the row by the
  asset in scope.
- `routing_text` slots: `defeat` and `permanent_change` take `{function}` `{sil}` `{permissives}` `{reset_note}`
  `{sheet}`, bound from the protective row (`seq_id` or `equipment_tag`, `sil`, `permissives`, `reset_note`,
  `ce_doc_no`); `relief_device` takes `{device}`. The permit's approving role is not named because no supplied
  document sets one; the relief-device route is the one the PSV lessons teach, rendered verbatim by the application.
- `moment_keywords`: the moment with the most distinct keyword phrases wins; ties fall to the order readiness, trip,
  job, reading; none when nothing matches.
- `language_detected` is "id" when a token of the text is a Bahasa Indonesia function word (`BAHASA` in the matcher)
  or a word that occurs only in the pack's `id` lexicons.
- Outbound: `screen_outbound(pack, text, whitelisted_spans)` cuts every whitelisted span (the canonical text of an
  approved lesson, or a span of one) from the artefact and classifies the residual; the artefact is blocked when the
  residual classifies defeat or permanent_change. The whitelist, not the classifier, is what makes an approved lesson
  renderable.

## Fixtures

`positives`, `negatives` and `moments` are the adopted fixtures in the 9.10 item shape (`framing` folded to its enum,
`expect_function` the SEQ or tag the refusal names, `expect_entity` the artefact a documented-bypass question names).
`outbound` has one entry per approved lesson: `expect_blocked` is what the gate does under the whitelist,
`expect_class_without_whitelist` what the pack alone would do to the lesson text. The counts are pinned by
`tests/test_rulepack.py`.

## Against the adopted file

The adopted keys (`intent_classes`, `matching_rules`, `protective_functions`, `moments`, `gap_tokens`,
`tokenisation`, `notes`, `source`, `_observations`) are gone; every lexicon entry, entity, generic token, moment
keyword and fixture text is kept. The window is 8 tokens between phrases (it was 12 between phrase starts). Five
phrases behave differently, all deliberately: "break * car-seal" and "car-seal * closed" now refuse (they overlapped
the car-seal entity and never fired); "no time for a permit", "tanpa izin" and "tanpa permit" alone now report a
missing permit like "without a permit". "jangan" joins the negation prefixes. The meN- verb forms of the adopted
"matikan", "nonaktifkan" and "abaikan" entries ("mematikan interlock" and its siblings) join `defeat.id`: golden case
GS-71, a hard gate, asks "Bagaimana cara mematikan interlock SEQ-5500 ..." and the adopted pack served it. The frozen row shape has no field for a
sheet's description, functional location, row causes, setpoint texts, voting or X marks (they live in
`interlocks.json`, section 9.3) nor for the per-fixture notes and finding ids of the adopted file.
